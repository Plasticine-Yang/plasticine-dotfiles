# Retire removed managed resources explicitly

When a selected Desired State no longer contains an active Component or Managed Path recorded in Reconciliation State, Plan will expose a Retirement rather than silently orphaning it. Apply may remove unchanged managed configuration, integration shims, launchers, and Managed Tool payloads and then release their ownership; Owner drift does not match the last accepted content, so it is a Conflict and is deleted only after `--adopt` creates the normal immutable backup. System Dependencies are never uninstalled, Tool-managed State is never deleted, and a Suspended Component remains untouched with Doctor reporting that its catalog definition disappeared. Selecting an older compatible Release applies the same rules to resources introduced by a newer Release, so rollback remains bounded and observable.
