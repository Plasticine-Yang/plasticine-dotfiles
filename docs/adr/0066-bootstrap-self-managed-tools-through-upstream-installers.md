# Bootstrap self-managed tools through upstream installers

Reconciliation may introduce or repair a Self-managed Tool by running its mutable upstream installer when its fixed primary executable is absent or cannot report a version, after which the tool owns its executable paths and version lifecycle. Plan checks the installer's local prerequisites and exposes its URL and external-script risk without claiming to know its internal changes; ordinary Apply authorization is sufficient, execution is bounded, and failure remains isolated to the Component without guessed rollback. Plasticine accepts an existing runnable installation without adoption, records no installation history, ignores aliases and versions, does not treat self-updates as drift, and preserves the tool when its Component is excluded or retired. This deliberately trades reproducible installation, exact Plan detail, and Plasticine-owned paths for the tool's native installation and self-update flow.

Self-managed Tool is a reusable Desired State category rather than a `tsm` special case, but its Release-declared interface stays narrow: an HTTPS installer URL with no local override, a fixed primary executable and health command, local prerequisite capabilities, and a timeout. Plan performs no network probe; Apply downloads the script to a temporary file, runs it with the Workstation's normal environment and visible output, and honors cancellation. This is a narrow exception to ADR 0014's complete Plan detail, ADR 0054's Plasticine Home ownership, and ADR 0060's Tool Lock-only Apply network egress.
