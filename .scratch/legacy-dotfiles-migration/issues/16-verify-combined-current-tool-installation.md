# 16: Verify combined installation and cross-Feature recovery

**What to build:** Prove that the individually delivered migrations and update routes work together through the real installer and chezmoi interfaces. Deliver integrated coverage and any required cross-Feature fixes for complete selection, independent updates, cancellation, partial failure, safe retry, and release-entrypoint behavior; this is not a substitute for each preceding ticket's own tests and documentation.

**Blocked by:** 08 — Keep chezmoi current on every installer invocation; 09 — Migrate independently selectable Git configuration; 10 — Update selected Lazygit to the latest stable release; 11 — Update the selected shell ecosystem through native mechanisms; 13 — Install and update Neovim from official stable archives; 14 — Migrate independent fnm installation and updates; 15 — Add Herdr through its official installer and native updater.

**Status:** ready-for-agent

- [ ] Demonstrate full intended Feature Selection through both interactive and explicit non-interactive installer paths, including Git configuration, Neovim, fnm, Herdr, shell, Lazygit, and a controlled GitHub SSH setup. Option order must not change selection or effects.
- [ ] Verify meaningful independent and partial combinations, including standalone fnm and Herdr, configuration-only selection, and empty selection. No Feature is implicitly selected, Git/OpenSSH are not upgraded by configuration Features, and unselected tool state remains uninspected by feature-specific work.
- [ ] Confirm the global version contract: each selected versioned tool checks its current permitted target; missing tools install, outdated supported tools update, and current tools avoid unnecessary replacement. Zsh retains its system/APT exception; Homebrew targets are correctly described as formula availability.
- [ ] Exercise a subsequent invocation after controlled upstream targets change for several tools at once. Verify all selected applicable tools and plugin ecosystems advance while unselected tools and already-satisfied managed configuration remain unchanged.
- [ ] Verify selected local configuration validation precedes the first selected-tool mutation, all selected executables prepare before managed configuration effects, configuration-dependent native plugin updates complete before final readiness, and recorded modes are restored before the login-shell transition.
- [ ] Cover failure at more than one cross-Feature stage: latest resolution before preparation, a later tool failing after an earlier tool updated, configuration failure, plugin synchronization failure after configuration, and final native login-shell refusal. Check actual retained state, nonzero outcome, backup preservation, and actionable completed/incomplete reporting.
- [ ] Retry each representative partial-failure scenario with the failing dependency repaired. Already-current tools must not be needlessly reinstalled, unchanged configuration must not acquire redundant backups, and the remaining work must complete without automatic uninstall or destructive rollback.
- [ ] Cancellation and dry-run cause no selected updates or latest-target queries. Verify separately that reported chezmoi/source prerequisite maintenance can precede selected-feature confirmation and is not falsely promised to be undone on cancellation.
- [ ] Test combinations sharing native Homebrew effects, including shell and macOS fnm. Preserve permitted ownership, native credential behavior, correct refreshed targets, and absence of broad or unrelated package upgrades; do not add a legacy batching framework solely for test convenience.
- [ ] Verify Neovim uses the complete current distribution and native plugin data tree after upgrade, and that plugin failures cannot be hidden by a successful executable health check. Retain real editor startup, representative shortcuts, file-tree, and terminal checks in disposable environments.
- [ ] Verify real-Zsh startup with the updated shell ecosystem, guarded fnm activation, later Owner overrides, and the exact existing Lazygit alias. Retain selected Integration Block byte preservation and one backup per changed shared entrypoint.
- [ ] Verify Git local overrides remain authoritative and untouched, Herdr never launches or silently stops sessions, and no fnm operation changes Node installations or defaults. Use distinct state sentinels across Features to detect unintended cleanup or takeover.
- [ ] Cover permitted-route and unsupported-owner failures, stable/prerelease handling, candidate publication races, integrity failures, and current-target postchecks in the integrated suite where Feature ordering could otherwise hide a problem.
- [ ] Run the existing automated platform matrix with controlled network, package-manager, updater, and credential fixtures. Keep real-runtime checks isolated and distinguish the separately authorized current-upstream Neovim/plugin smoke check from deterministic automated tests.
- [ ] Preserve release provenance and verify the released installer uses the new current-tool policy while retaining its own source revision identity. Do not remove unrelated CI integrity pins or deterministic test versions.
- [ ] Reconcile user documentation with the delivered command surface, latest/stable semantics, the Zsh and macOS fnm exceptions, configuration ownership, native update effects, prerequisites, and failure recovery. Do not advertise unsupported native-owner migrations or transaction-wide rollback.
- [ ] Confirm the rejected legacy Features remain absent from new selection and do not become automatic uninstall targets. Preserve the historical completed status of tickets 01–06 and do not modify or close the parent spec as part of this ticket.
- [ ] Mark this ticket done only when the approved behavior is implemented, the integrated and existing regression suites pass, relevant real-runtime verification is recorded, and no preceding feature is being treated as complete merely because its verification was deferred here.
